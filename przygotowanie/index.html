Zanim przyjdziesz na szkolenie: miej zainstalowane to, czego potrzebujemy, pobrany kod i sprawdź, że system odpala się u Ciebie lokalnie. Lista jest celowo minimalna.

🔴 Zmiany

Przygotowanie zmieniło się po wysłaniu zaproszenia. Jeśli zrobiłeś je wcześniej, raz przed szkoleniem pobierz nowe repo i skille (w katalogu repo):

⌨️ Terminal
cd campsite-power-acc
git pull
git -C .claude/skills fetch -q
git -C .claude/skills switch -f czysto
git -C .claude/skills reset -q --hard '@{u}'
cd campsite-power-acc
git pull
git -C .claude/skills fetch -q
git -C .claude/skills switch -f czysto
git -C .claude/skills reset -q --hard '@{u}'

Potem jeszcze raz zainstaluj narzędzie z sekcji „Na koniec” (na dole strony). Inne zmiany: Node.js 22+ zamiast 20, nowe kroki drogi B (mvn install, PostgreSQL) i port 5432 w drodze A.

Co musisz mieć — minimum

Zawsze:

  • Claude Code — tu dzieje się całe szkolenie. Instalacja: docs.claude.com/claude-code. Po instalacji w terminalu działa komenda claude.
  • Git — do pobrania kodu. Sprawdź: git --version. Brak? → git-scm.com/downloads (na Windows komendy wklejasz do PowerShell; przy każdej komendzie jest przełącznik „Windows”).
  • Node.js 22+ (22.13 lub nowszy) — do narzędzi i skryptów skilli szkoleniowych (nie instaluje się razem z Claude Code). Sprawdź: node -v. Brak? → macOS brew install node, Windows winget install OpenJS.NodeJS.LTS, Linux nodejs.org.

Do uruchomienia systemu — wybierz jedną drogę:

Droga A (zalecana): Docker

Jeden program — stawia bazę i aplikację, nic więcej nie instalujesz.

  • Docker Desktop — docker.com/products/docker-desktop. Sprawdź: docker --version.

Droga A z Podmanem (gdy nie masz Dockera)

Te same kroki co w drodze A, tylko komendą podman zamiast docker.

  • Podman — podman.io: macOS brew install podman, Windows winget install RedHat.Podman, Linux z menedżera pakietów (sudo apt install podman). Sprawdź: podman --version.
  • Na macOS i Windows raz uruchom maszynę Podmana: podman machine init, potem podman machine start (Linux tego nie potrzebuje).

Droga B (bez Dockera): Java 21 + Maven + PostgreSQL 16

Potrzebne, jeśli nie chcesz Dockera (Node 22+ masz już z minimum). Najprościej menedżerem pakietów:

⌨️ Terminal
# macOS (Homebrew – https://brew.sh)
brew install openjdk@21 maven postgresql@16

# Linux (Debian/Ubuntu – JDK + Maven z repo)
sudo apt install openjdk-21-jdk maven postgresql
winget install EclipseAdoptium.Temurin.21.JDK
winget install Apache.Maven
winget install PostgreSQL.PostgreSQL.16

Uruchom PostgreSQL i załóż bazę (użytkownik campsite, hasło campsite):

⌨️ Terminal
# macOS: postgresql@16 nie trafia sam do PATH (w nowym terminalu powtórz export)
brew services start postgresql@16
export PATH="$(brew --prefix postgresql@16)/bin:$PATH"
createuser -P campsite                      # hasło: campsite
createdb -O campsite campsite_power

# Linux: jako użytkownik postgres
sudo -u postgres createuser -P campsite     # hasło: campsite
sudo -u postgres createdb -O campsite campsite_power
$env:Path += ";C:\Program Files\PostgreSQL\16\bin"   # winget nie dodaje Postgresa do PATH
createuser -U postgres -P campsite         # dwa razy hasło campsite, potem hasło użytkownika postgres z instalacji
createdb -U postgres -O campsite campsite_power

Sprawdź: java -version (→ 21), mvn -v, node -v (→ 22+), psql --version (→ 16). Na Windows po każdym winget install otwórz nowe okno PowerShell, inaczej nowej komendy nie widać.

Sprawdź, że się uruchamia

Uruchom tylko swoją drogę. System działa na http://localhost:8080 (droga A) albo http://localhost:5173 (droga B), login admin / demo-admin. Błędy z adria-club.example w logu są normalne: to partner demo bez serwera.

Droga A: Docker

⌨️ Terminal
docker compose up -d                       # baza PostgreSQL 16
docker build -t campsite-power .
docker run -p 8080:8080 -e CAMPSITE_DB_HOST=host.docker.internal campsite-power
docker compose up -d                       # baza PostgreSQL 16
docker build -t campsite-power .
docker run -p 8080:8080 -e CAMPSITE_DB_HOST=host.docker.internal campsite-power

Port 5432 zajęty (port is already allocated, np. masz lokalnego Postgresa)? Postaw bazę na innym porcie i podaj go aplikacji:

⌨️ Terminal
CAMPSITE_DB_PORT=5440 docker compose up -d
docker run -p 8080:8080 -e CAMPSITE_DB_HOST=host.docker.internal -e CAMPSITE_DB_PORT=5440 campsite-power
$env:CAMPSITE_DB_PORT=5440; docker compose up -d
docker run -p 8080:8080 -e CAMPSITE_DB_HOST=host.docker.internal -e CAMPSITE_DB_PORT=5440 campsite-power

Droga A z Podmanem (po podman machine start na macOS i Windows)

⌨️ Terminal
podman run -d --name campsite-power-pg -p 5432:5432 -e POSTGRES_DB=campsite_power -e POSTGRES_USER=campsite -e POSTGRES_PASSWORD=campsite docker.io/library/postgres:16
podman build -t campsite-power .
podman run -p 8080:8080 -e CAMPSITE_DB_HOST=host.containers.internal campsite-power
podman run -d --name campsite-power-pg -p 5432:5432 -e POSTGRES_DB=campsite_power -e POSTGRES_USER=campsite -e POSTGRES_PASSWORD=campsite docker.io/library/postgres:16
podman build -t campsite-power .
podman run -p 8080:8080 -e CAMPSITE_DB_HOST=host.containers.internal campsite-power

Na koniec: narzędzie, którego użyjemy na szkoleniu

Instalacja (jedna komenda):

⌨️ Terminal
rm -rf /tmp/legacy-ai-skille && git clone --depth 1 https://github.com/pilloPl/legacy-ai-skille.git /tmp/legacy-ai-skille && mkdir -p ~/.claude/skills && cp -R /tmp/legacy-ai-skille/harness-lens ~/.claude/skills/
Remove-Item -Recurse -Force $env:TEMP\legacy-ai-skille -ErrorAction Ignore; git clone --depth 1 https://github.com/pilloPl/legacy-ai-skille.git $env:TEMP\legacy-ai-skille; New-Item -ItemType Directory -Force $HOME\.claude\skills | Out-Null; Copy-Item -Recurse -Force $env:TEMP\legacy-ai-skille\harness-lens $HOME\.claude\skills\

Sprawdzenie — wystarczy, że ta komenda wypisze gotowe (narzędzie uruchomimy razem na szkoleniu):

⌨️ Terminal
node --check ~/.claude/skills/harness-lens/lens.mjs && echo gotowe
node --check $HOME\.claude\skills\harness-lens\lens.mjs; if ($?) { "gotowe" }

Spokojnie z rm -rf (i Remove-Item na Windows): kasuje wyłącznie tymczasowy katalog legacy-ai-skille po ewentualnej wcześniejszej instalacji, żeby git clone pobrał świeżą kopię — nic poza nim nie jest usuwane.
